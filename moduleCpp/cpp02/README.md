# 연산자 오버로딩

## 1. 연산자 오버로딩(재정의)은 무엇인가?

- 연산자 재정의를 하면 내가 정의한 클래스에서도 연산자를 쓸 수 있게 된다.
- C++에서는 아래의 연산자를 재정의 할 수 있다.
```
+, -, *, /, %, ^, &, |, ~, !, =, <, >, +=, -=, *=, /=, %=, |=, <<, >>, >>=, <<=, ==, != <=, >=, &&, ||, ++, --, ,, ->*, ->, ( ), [ ]
[C++ 20 추가: <=>]
```

## 2. 오버로딩 할 수 없는 연산자
```
::, . (멤버 변수/함수 접근), .*, ? 연산자는 오버로딩 할 수 없다.
=, (), [], -> 는 멤버 함수로만 구현할 수 있다.
```

## 3. 연산자 오버로딩 방법

```
std::ostream	&operator<<(std::ostream &os, const Fixed &fixed)
{
	return (os << fixed.toFloat());
}
```

<< 연산자의 앞에 오는 인자를 첫번째로, 뒤에 오는 인자를 두번째 파라미터로 넣어서 연산자 오버로딩 함수를 구현한다. output을 담당하는 ostream에 << 연산자를 통해 값을 전달할 수 있도록 이미 구현되어 있으므로 우리는 클래스에서 어떤 값을 뽑아서 넣어줄지만 구현해주면 된다. 중요한 것은 클래스 밖에다 선언하는 것!!
연산자는 엄밀히 따지면 다음과 같이 기능한다.

```
NUMBOX operator+(NUMBOX &ref)
{
	return NUMBOX(num1+ref.num1, num2+ref.num2);
}

//이항 연산자의 왼쪽에 오는 객체의 operator + 함수를 호출 하면서, 이항연산자의 오른쪽의 피연산자를 인자로 전달한다
nb1 + nb2 = nb1.operator+(nb2)
```



# Fixed Point Value

동일하게 보이는 부동 소수점 숫자가 반드시 C의 "=="테스트를 충족하지 못할 때가 종종 있다. 부동 소수점 수에 ==를 사용하지 않는 것이 권장된다. 부동 소수점 숫자를 프로그램에서 효율적으로 사용하기 위해는 몇 가지를 알고 있어야 한다.
"정확도"는 실제 값에 측정값이 얼마나 가까운지를 의미하고, "정밀도"는 양에 대해 얼마나 많은 정보를 가지고 있으며 얼마나 정확하게 수를 pinned down 했는지와 관련이 있다.

정수는 정밀도가 결핍되어 있다. 5와 4를 2로 나누면 모두 2가 도출되지만, 정수는 그 나머지 부분을 추적할 수 없기 때문에 4보다 약간 더 큰 수(즉, 5)는 그 과정에서 영영 소실되고 만다.

== 연산자는 비교되는 두 수의 부동 소수점이 정확하게 같은지(즉, 비트가 일치하는지) 알려준다. 그러나 비트 중 일부가 부정확할 수 있을 때, 비트를 비교하는 것은 별 의미가 없다. float의 정확도가 제한된다. 결과는 한정된 만큼 반올림되어야 하며 CPU 및 소프트웨어가 예상대로 반올림 되지 않으면 equality 테스트가 실패할 수 있다.

프로그래머는 일반적으로 EPSILON 만큼의 차이를 "충분히 가까움"으로 정의하고 두 숫자가 그렇게 가까운지 확인하여 equality를 테스트한다. 다음과 같이 진행됩니다.

```
#define EPSILON 1.0e-7 
#define flt_equals(a, b) (fabs((a)-(b)) < EPSILON)
```

복잡하니까 간단히 말해보자면 고정소숫점은 10진수 수를 2진수로 바꾸는 일반적인 방법 그대로 수를 표현하는, 컴퓨터에서 사용하는 방식이다.

예를 들면 7.625라는 실수가 있다고 치자. 2진수로 변환하면 111.101이 될 것이다. 이걸 이렇게 저장한다.

소수점 아래 자리를 이진법으로 변환하는 과정은 다음과 같다.
```
0.625 * 2 = 1.25 -> 1을 빼내고 나머지 0.25
0.25 * 2 = 0.5 -> 0을 빼내고 나머지 0.5
0.5 * 2 = 1.0 -> 1을 빼내고 나머지 0
나머지 0이 나왔으니 변환을 종료하고 빼낸 숫자들을 위에서부터 읽어주면 된다. 즉 0.625 -> 0.101이 된다.
```

```
     0 | 0000111 | 10100000
부호비트 |   정수부  |  소수부
```

맨 앞 1자리는 부호 비트 (Sign Bit) 라고 해서 0이면 양수, 1이면 음수라는 뜻이다. 나머지 비트들은 소수점을 기준으로 정수부랑 소수부를 표현하는 비트로 각각 나누게 되는데, 소수점의 위치는 미리 정해둔다.

소수부의 경우 앞에서부터 채우며 남는 뒷자리는 다 0으로 채운다. 이러한 고정소수점 방식은 구현하기 편리하지만 사용하는 비트 수 대비 표현 가능한 수의 범위 또는 정밀도가 낮기 때문에 실수를 다룰 필요가 있는 범용 시스템에서는 거의 안 쓰이고, 높은 정밀도가 필요없는 소규모 시스템에서는 간혹 쓰이기도 한다고 한다.


### 부동 소수점

표현 가능한 수의 범위가 적다라는 고정소수점의 단점을 보안하기 위해 고안된 것이 부동소수점 방식이다.
부동소수점 표현 방식에서는 2진수로 변환한 결과를 그대로 박아넣지 않고 몇 가지 과정을 추가로 거친다.


#### 정규화


IEEE 표준에 따르면 부동소수점 방식으로 실수를 저장하는 데는 32비트, 또는 64비트가 사용된다.

7.625라는 수를 부동소수점 방식으로 표현해 본다고 하자.
23자리 가수부는 정규화 결과 소수점 오른쪽에 있는 숫자들을 왼쪽부터 그대로 넣으면 된다. 남는 자리는 0으로 채운다.

남은건 8자리짜리 지수부인데, 일단 '지수' 부라는 이름으로 봤을 땐 2^n에서 n에 해당하는 수, 그러니까 예시에서는 2를 2진수로 바꾼 '10' 을 넣으면 될 것 같다.

근데 IEEE 표준에 따르면 저 부분에는 지수를 그대로 박아넣는게 아니라, 'bias' 라고 하는 지정된 숫자를 더한 다음 넣어야 한다.

IEEE 표준에서 32비트를 쓰는 경우 bias는 127이라고 규정하고 있다. 따라서 2 + 127 = 129를 2진수로 바꾼 10000001이 들어간다.
